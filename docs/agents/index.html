Miri for Agents

Miri is built to be written by coding agents — Claude Code, Cursor, Codex and the like — with a person reviewing the result. The compiler explains every mistake in words an agent can act on, often hands it the exact fix, and answers lookup questions so the agent never has to guess a name. This guide shows how to set that up and how each tool works, with real output from the current compiler.

What Agents Get

An agent writing code does best when it can try something, see exactly what went wrong, and fix it without guessing. Miri gives it these tools, all in the miri command:

ToolWhat it does for the agent
The loopOne short routine — check, fix, test — that the agent repeats until the code is clean.
miri check --format jsonEvery error and warning as JSON: a stable code, the exact place, a one-line help, and often a ready-made repair.
miri fixApplies those repairs to the file in one call.
miri explainDescribes the rule behind any error code, with a before-and-after example.
miri viewAnswers “what can I call on this type?” and “what does this module offer?” from the real standard library.
miri testRuns @test functions and reports each failure with the expected and actual values.
miri patchEdits inside one function and refuses the edit if the file would stop compiling.
Skill packsShort guides the agent reads before writing Miri: the syntax, the traps, and the loop.
{% include agents/counts.html %}

Why this matters: an agent that has to guess pays for every wrong guess with another round trip. When the compiler names the rule, points at the spot and offers the edit, most mistakes cost one step to fix.

Set Up in Two Commands

1. Install the compiler

You need the Rust toolchain and a C compiler (cc; on macOS run xcode-select --install, on Debian or Ubuntu apt install build-essential). Then:

git clone https://github.com/miri-lang/miri.git
cd miri
make install

make install builds the compiler and puts a miri link in ~/.local/bin. If that directory is not on your PATH yet, the command prints the line to add. Keep the clone where it is: the link points into it. To install somewhere else, pass BINDIR, for example make install BINDIR=/usr/local/bin.

3. Check it works

Ask your agent for something small, like “write a Miri program that prints the sum of a list”. A set-up agent writes the file, runs miri check on it, and fixes what the compiler reports, without being told how.

Agent without skills support? Add one line to the instructions file it reads (AGENTS.md, CLAUDE.md, a rules file): “This project is written in Miri. Read skills/miri-lang/SKILL.md before editing .mi files, and run miri check FILE --format json after every edit.” Then install with --agent generic.

Updating

Pull, rebuild and refresh the packs:

cd miri && git pull && make install
cd your-project && miri skill install

Each installed pack records which compiler wrote it and a fingerprint of its text. A pack nobody has edited is updated in place. A pack you edited is left alone and reported (code MER_BLD_014); add --force to replace it anyway.

Without the compiler on hand

The packs are plain Markdown files in the compiler repository, so you can also copy one directly:

mkdir -p .claude/skills/miri-lang
curl -o .claude/skills/miri-lang/SKILL.md \
  https://raw.githubusercontent.com/miri-lang/miri/main/skills/miri-lang/SKILL.md

The agent still needs miri on its PATH to run the loop.

Reading Diagnostics

Without --format json, miri check prints errors for people:

{% include agents/run.html session="check-pretty" step=0 %}

With --format json it prints the same information as one JSON object on standard output. Every command that takes --format json — check, build, run, test, fix, explain, view, patch, skill — answers in this same shape, so an agent only learns to read it once.

The fields an agent needs most:

  • ok — whether the command did what was asked. Warnings never make it false.
  • exitCode — the same number the process exits with.
  • diagnostics — one entry per problem, each with:
    • code — a stable name such as MER_TYP_042. Pass it to miri explain for the full rule.
    • line, column and length — where the problem is, counted in characters from 1.
    • help — one sentence on what to do instead.
    • repair — when present, the exact edits that fix it: byte offsets start and end in the file, and the replacement text. miri fix applies them for you, or an agent can apply them itself.
    • fixSafety — how safe the fix is to apply without a person looking (see Repairs).

Every field is listed in the JSON reference.

Repairs — miri fix

A repair is an edit the compiler is sure of. When a diagnostic carries one, miri fix can write it. Without --apply it only shows what it would do:

{% include agents/run.html session="fix-preview" step=0 %}

miri fix FILE --apply --yes writes every repair in the file in one go. (--yes confirms the write when there is no terminal to ask at, which is always the case for an agent.)

How safe is a repair?

Every diagnostic code has a fixSafety level. miri fix --apply writes the first three on its own and refuses the rest unless you add --allow-risky:

LevelMeaningApplied by default
format-onlyChanges layout only.yes
behavior-preservingChanges the text, not what the program does.yes
local-editChanges one spot, and nothing outside it can notice.yes
api-changingChanges something other code relies on, such as a parameter name callers can pass by name.no
target-changingChanges where or how the program runs, such as moving data to the GPU or narrowing a number.no
requires-human-reviewPlausible, but a person should look first.no

Lookups — miri view

Agents often guess method names from other languages: .len(), .to_string(), .keys(). miri view answers from the real standard library instead, so one lookup replaces a string of wrong guesses.

Tests — miri test

Mark a function with @test and miri test finds and runs it. Each test runs in its own process, so a crash fails one test instead of the whole run. Here is a file with a deliberately wrong expectation in its second test:

With --format json, each failure carries the code, the line and the expected and actual values, ready for the agent to compare:

{% include agents/run.html session="test" step=1 %}

The exit status says what happened: 0 all passed, 1 a test failed, 2 no test ran at all (a file did not compile, or there were no tests). An agent can trust a 0: a run that found nothing to test is never reported as a pass. The miri-testing pack covers assertions and test attributes.

Scoped Edits — miri patch

miri patch replaces text inside one named function, then checks the whole file before saving. A good edit is written:

{% include agents/run.html session="patch" step=0 %}

An edit that would break the file is refused, and the file is left exactly as it was:

{% include agents/run.html session="patch" step=1 %}

The text to replace must appear exactly once inside the function. patch works on files in Miri's standard layout, so run miri fmt FILE first if the file was written by hand. Ordinary file edits work just as well; patch is there for when you want the check before anything is saved.

For Editors — miri agent

An agent with a shell should use the commands above. miri agent is for tools that want to keep one compiler running instead of starting it for every command — an editor plugin, or a service with no shell. It speaks JSON-RPC 2.0 over standard input and output, framed with a Content-Length header the way a language server is:

→ {"jsonrpc":"2.0","id":1,"method":"check","params":{"path":"main.mi"}}
← {"jsonrpc":"2.0","id":1,"result":{"schemaVersion":1,"ok":false,"command":"check","diagnostics":[…]}}

→ {"jsonrpc":"2.0","id":2,"method":"fixApply","params":{"path":"main.mi"}}
← {"jsonrpc":"2.0","id":2,"result":{"schemaVersion":1,"ok":true,"command":"fix","diagnostics":[…]}}

Each method answers with exactly the JSON its command prints. The methods are initialize, check, explain, fixApply, view, patch and skillsGet, and $/cancelRequest cancels one in flight. The full protocol is in docs/agent-protocol.md, and tools/agent_client.py is a small working client in Python.
